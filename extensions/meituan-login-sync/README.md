# 美团登录同步扩展（第一版）

使用日常 Edge 或 Chrome 完成人工登录，由用户点击读取当前浏览器配置文件中的五类 Cookie，导入同机采集服务。
不自动登录、不解验证码、不伪装浏览器、不监听全部流量、不改写浏览器 Cookie、不上传云端。

当前版本 0.2.2：酒店核对直接使用已登录的普通浏览器评价页，不再为扩展核对启动另一个无头 Edge。请先在安装扩展的同一窗口打开美团“评价管理”，待列表加载完成后点击读取。扩展只在这次点击后通过 `scripting` 在该页面执行一次只读评价请求，返回酒店参数、HTTP/业务码和酒店名摘要；评价正文、住客信息、页面存储不会发送到本机。此能力使用 Chromium 官方 scripting API，见 [官方文档](https://developer.chrome.com/docs/extensions/reference/api/scripting)。

0.2.2 补齐原有固定站点的 HTTP Cookie 读取权限：Chromium Cookie API 会用 Cookie 的 Secure 属性对应的协议检查权限，只有 HTTPS 权限时可能漏掉 Secure=false 的登录 Cookie。程序仍只在 HTTPS 评价页核对，不向 HTTP 美团后台发送请求。前后端都要求 ME 包含非空 mebsid、EB 包含非空 ebbsid，缺失则拒绝整批导入；额外后台如果只有 uuid 和已知 __rcf 公共标识，会显示未读取并保留原配置。先前已经写入的残缺值无法凭代码补回，需重新加载 0.2.2 扩展并重新读取。首次加载后的站点权限若有提示，由用户在扩展管理页查看并启用。

0.2.1 修复上一版重新构造请求时写死 `offset=0、limit=1` 的问题。现沿用评价页已产生请求的页码、条数、平台和接口版本等参数，只删除旧签名并由页面生成新签名；忽略上一版留下的零页码请求记录。业务码 1000 继续视为未成功，不据此认定 Cookie 过期。若接口消息包含可识别的参数、签名、登录、人工验证或权限提示，侧栏仅显示对应固定类别，不回传原始消息。

权限仅包含五个后台、父域 `meituan.com` / `dianping.com`（读取后台共享的父域 Cookie 所必需）及本机回环地址；没有申请所有网站或全部子域名权限。

从 0.1.1 起，点击扩展图标打开浏览器原生侧栏，不再使用跟随工具栏图标的浮窗。界面随侧栏宽度适配；侧栏左右位置由浏览器设置决定，扩展不修改浏览器全局偏好。如果显示在左侧，请在浏览器的侧栏/外观设置中选择右侧。

从 0.1.2 起，酒店核对失败仍保留本轮读取摘要，显示“已读取·未保存”，不会把核对失败当成未读取或配对失效。顶部显示具体安全原因及 HTTP/业务码；酒店不一致时显示当前和本次识别的门店 ID。失败批次不能保存，可以取消，或在检查正常页面后主动点击“重新读取并核对酒店”。不会自动重试。

从 0.1.3 起，侧栏显示“实际跳转到登录页：是/否”（仅在读取到核对页面地址时）；只有隔离核对会话确实落在美团登录页才报告登录跳转。页面正文单独出现“登录”不会被误报为跳转。改动后须重启采集面板、在扩展管理页重新加载本项目目录；核对仍未通过时请提供原因编号、阶段及 HTTP/业务码，不要提供 Cookie 或签名网址。

从 0.1.4 起，核对用的隔离会话按浏览器读取到的原始域名、路径和安全属性载入 Cookie，不再把每个 Cookie 扩展到 ME/EB 多个域名。保存给采集任务的配置字段与格式不变。真实登录是否可在隔离会话中复用，仍由评价接口核验；失败不会覆盖原配置。

## 安装及首次连接

1. 更新并重启采集面板。原先运行中的旧进程不会自动加载新代码。
2. 扩展随整个项目交付，无需单独下载或解压扩展包。直接使用项目内的 `extensions/meituan-login-sync` 目录，不要删除或频繁移动该目录。
3. 打开 `edge://extensions/`，启用“开发人员模式”，选择“加载解压缩的扩展”，选中上述直接包含 `manifest.json` 的项目目录。Chrome 对应 `chrome://extensions/`。最低 Chromium 132。
4. 扩展必须安装在日常登录美团的同一个普通浏览器配置文件中；不支持无痕窗口。
5. 从本机配置中心点击“浏览器扩展导入”，或访问 `http://127.0.0.1:8765/browser-cookie-import`。自定义服务端口时相应修改网址和扩展端口。
6. 生成一次性配对码，将其粘贴到扩展后点击“连接本机服务”。配对码三分钟有效，成功后立即作废；连续五次输错需重新生成。

## 每次更新登录状态

不需要每次同时打开五个独立页面。Cookie 从同一普通浏览器配置文件的 Cookie 仓库按域读取；首次登录、切换账号或后台会话过期时，需要正常访问相应功能，让该后台建立会话。评价页和数据中心分别用于建立 ME、EB 会话；推广、酒店亮点和公益流量按实际采集需求访问，菜单打开的内嵌页面同样可以建立对应域的 Cookie。核对时保留评价页打开，其他后台页面不必全部保留。

1. 暂停自动采集、调价、评价回复和推广控制调度，等待后台进程和正在执行的任务结束，关闭登录助手。
2. 在普通浏览器完成登录，在同一窗口打开美团“评价管理”，等待列表加载完成。需要推广、酒店亮点或公益后台时，正常打开相应功能建立会话。
3. 点击扩展“读取 Cookie 并核对酒店”。只在此刻读取 Cookie。
4. 等待核对，核实酒店名称及门店 ID，并确认五类后台属于同一账号。额外后台显示“已读取”不代表已验证有效。
5. 点击“确认保存到采集服务”。成功后可在配置页刷新查看酒店信息，再恢复需要的调度。导入本身不会采集或写数据库。

核对读取当前评价页已有的酒店请求参数，使用页面现有请求代码发出一次新的只读请求，由页面正常生成签名。收到 HTTP 200、业务码 10000、有效响应及对应酒店参数后才进入待确认。不会重放已有签名、自动刷新页面或自动重试；没有评价页或请求记录时提示用户检查页面。请求完成后重新读取 Cookie，以取得页面正常更新后的会话值。酒店名优先来自响应中的酒店名称字段；接口未提供名称时，仅在成功核对为当前已配置酒店后保留原酒店名称。第一次配置缺少名称时需先填写名称，不从评价正文猜测。

## 保存范围与保护

| 站点 | 当前配置字段 |
|---|---|
| me.meituan.com | meituan.me_cookie |
| eb.meituan.com | meituan.eb_cookie |
| ebmidas.dianping.com | meituan.promotion_cookie |
| tdc.meituan.com | meituan.highlights_cookie |
| gongyi.meituan.com | meituan.public_welfare_cookie |

- ME、EB 必须都读取到；额外后台未读取时，不覆盖同酒店原值。请人工检查额外后台账号；第一版不独立认证每个后台。
- 识别酒店与当前已配置 `poi_id` 不同会阻止导入，不能用扩展静默切换酒店数据库。酒店未知且存在无法确认归属的旧后台 Cookie 时也拒绝不完整导入。
- 核对及等待确认期间暂时保护本地配置，阻止其他配置写入和新业务任务；取消或超时释放，保护最长四分钟。待确认数据仅在服务内存中保留三分钟。
- 窗口关闭后可重新打开扩展继续确认；浏览器/服务重启后可能需重新读取。保护未立即解除时请等待四分钟，不要删除浏览器配置目录。
- 同名 Cookie 不同值、分区 Cookie 或不能兼容现有 Cookie Header 的值直接拒绝，不静默合并。
- 仅更新指定 Cookie 与核验过的酒店参数，不修改任务清单、开关、PMS、数据库配置、采集冷却或 Schema。

## 授权、隐私及更新

只与固定 `127.0.0.1` 通信，不支持远程面板、代理转发或任意服务器地址。首次浏览器提示本机访问权限时需允许；企业策略阻止时请联系管理员，不要关闭浏览器安全保护。

配对令牌仅存在扩展本地存储；服务只保存其哈希及扩展 ID，三十天到期。Cookie 不存扩展存储、不经剪贴板、不回显或写日志。采集服务的 Cookie 仍按项目既有方式保存在本机真实配置中，应保护该目录，不要分享配置文件。

面板可撤销扩展授权，取消待确认数据但不清空已保存 Cookie；“重置本地配置”也撤销授权。单机其他恶意程序或具有同等高权限的扩展不属于此机制可以防御的范围。

扩展作为项目的一部分统一交付，不再单独生成 ZIP、校验文件或版本解压副本。更新项目后重启面板，并在扩展管理页点“重新加载”；0.2.0 新增 `scripting` 权限用于在现有美团评价页执行这一次核对，不扩大网站范围，也不注册常驻内容脚本。现有采集服务代码更新器的白名单不变，不自动安装或重新加载浏览器扩展。

如果之前加载的是 `dist/meituan-login-sync-0.1.0` 等临时目录，请移除旧扩展，再加载项目中的 `extensions/meituan-login-sync`。路径变化可能改变扩展 ID，需要重新配对；不会因此清空采集服务中已保存的 Cookie。
