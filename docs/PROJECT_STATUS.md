## 6. 房型和商品映射进度

### PMS 多房型归一

房型映射现在支持一个统一 `room_type_id` 对应多个 PMS 原始房型名称，用于解决“PMS 两个房型对应 OTA 一个房型”的实际场景。

当前规则：

- 多个 PMS 房型名称可以共享同一个统一 `room_type_id`。
- 同一个 PMS 原始房型名称不能同时属于两个不同统一房型 ID。
- 房型映射页面按 PMS 原始房型逐行展示；同一统一房型可出现多行，每行可单独停用。
- 行内停用只关闭当前 `pms_byh` 别名的精确匹配，不影响同一统一房型的其他 PMS 别名或 OTA 商品关系。
- 每个 PMS 别名单独保存为 `pms_byh` 基础映射记录；数据库现有唯一键已经支持这种多别名结构，不需要新增 Schema。
- 使用“新增”方式再次保存同一个统一房型 ID 时，会合并已有 PMS 别名，不再把旧 PMS 房型覆盖掉。
- 使用“编辑”方式可以明确移除某个 PMS 别名；被移除的别名不再参与后续匹配。
- PMS 业务表仍按原始房型名称精确匹配，因此不同 PMS 名称可以最终写入同一个统一 `room_type_id`。
- OTA 商品匹配、美团钟点房判断保持原有独立逻辑。

### 7.2 PMS 网络抖动保护

### 7.4 后台采集状态自动收尾

面板启动的整批采集会记录后台 `runner.py` 进程 PID。状态页读取时如果发现任务仍显示
“正在启动/运行/中断”，但对应进程已经退出，则自动将本轮及尚未执行的任务收尾：

- 已请求停止的任务标记为“已中断”。
- 未请求停止但进程异常退出的任务标记为“失败”，并说明未返回完成状态。

这样服务重启、子进程异常退出或中断后，不会长期把 PMS 等待执行任务显示为“进行中”。

面板只会对明确记录了后台 `runner.py` PID 的直接启动任务进行“进程已退出”自动收尾；
定时调度器直接运行的批次不带该 PID，必须保留实际的运行状态，避免页面将未执行任务误标为
0 秒失败并隐藏“中断当前采集”按钮。

携程商品采集完成后会将最新商品 ID、商品名、`product_cipher`、可调价标识和钟点房标识同步到
`hotel_room_type_mapping`；基础房型记录仍不保存商品级字段。

## 9. 浏览器与动态签名现状

当前美团部分采集依赖页面自己产生的动态签名请求，而不是保存一条长期不变的签名 URL。

已经存在公共浏览器 profile 锁，用于减少：

- 定时任务之间争抢 Edge profile。
- 人工登录/操作与自动采集同时占用 profile。

修改页面型采集代码前，应先确认是否依赖这套动态请求捕获和浏览器锁。

## 11. 已经确认、不需要重复争论的设计

为了避免新 Codex 会话重复排查已经确认的问题：

- 每个数据库只对应一家酒店，不需要优先考虑跨酒店同库隔离。
- 一个统一 `room_type_id` 允许对应多个 PMS 原始房型名称；不要把这种多对一关系自动判定为冲突。
- 同一个 PMS 原始房型不能同时映射到两个不同统一房型 ID。
- `ctrip_order_loss_monthly` 当前快照/排名语义是有意设计。
- 评价回复调度读取 `price_scheduler.interval_minutes` 是当前有意设计。
- 登录/账号切换自动识别酒店参数失败时保留旧参数并告警是有意设计。
- 美团商品 `is_hour_room` 和统一房型映射 `is_hour_room` 保持独立判断。
- PMS 00:00–05:59 查询当日 12:00 是经过实际运行确认的规则。
- ROOM_STATUS 的查询 `beginHour` 与真实 `snapshot_hour` 不一致并不代表数据错误。
- 美团页面型任务主动降低频率是为了降低访问压力和风险控制触发概率。

## 12. 当前应优先验证的事情

以下是下一次运行时值得优先观察的项目，不代表必须立即开发新功能：

1. **验证 PMS 多别名房型**：选两个 PMS 房型映射到同一统一 `room_type_id`，确认两种 PMS 名称的历史/新数据都写入同一 ID，且再次新增别名不会覆盖已有别名。
2. **跑一轮完整 PMS**：确认 JD01 0 条时能够继续执行 JD04、JY01、FORECAST 等后续 ETL。
3. **观察 PMS 网络熔断实际表现**：如果上游连接恢复，确认正常成功任务不会被误熔断。
4. **观察三个美团页面任务 state**：确认只有实际 success/failure 才生成新的 `next_allowed_at`，冷却期跳过不会延长冷却。
5. **观察 FORECAST 的 `room_type_id`**：确认可唯一映射的 PMS 房型正确写入统一 ID，歧义房型保持为空。

## 登录助手稳定性

登录助手现在提供面板中的“关闭登录助手”操作，并在退出时清空状态文件中的 PID。关闭前会校验 PID 对应的命令确实是登录助手，避免旧状态文件遇到 Windows PID 复用时误判或误结束无关进程。

## 13. 后续产品方向（非当前强制任务）

现有采集和数据库已经可以支持下一阶段从“数据采集工具”向“经营决策辅助”扩展，例如：
